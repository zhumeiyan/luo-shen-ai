【一、设计目标与美学哲学】

1.1 设计目标
  - 极简高级感：去掉一切不服务于对话的装饰元素
  - 声波/光晕/粒子：洛神作为"信息生命体"的视觉外化
  - 跨端无缝：折叠屏展开/收起时体验不跳跃
  - 单端通话：语音通话世界唯一，跨设备同步进行中状态

1.2 美学关键词
  「深海、电信号、呼吸、透明、震动、涟漪」

  色彩系统（深色色系）:
  ────────────────────────────────────────
  主色:        #0A0E1A  (深海黑蓝, 背景)
  辅助背景:   #131825   (面板底色)
  强调色:     #4FC3F7  (电光蓝, 洛神声波纹)
  次要强调:   #7C4DFF  (紫罗兰, 用户声波纹)
  温暖强调:   #FF8A65  (暖橙, 情绪高位)
  文字主色:   #E8EAED
  文字次色:   #9AA0A6
  边框:       rgba(255,255,255,0.06)
  ────────────────────────────────────────

1.3 排版系统
  - 基础字号: 16px (正文) / 14px (辅助) / 24px (标题), 按断点等比缩放
  - 中文: PingFang SC / Microsoft YaHei，英文/数字: Inter / DIN Alternate
  - 行高: 1.6 (正文) / 1.3 (标题)
  - 段落间距: 1rem 基准，紧凑模式 0.6rem

【三、声波-光晕-粒子视觉核心】

3.1 声波球 (Sonic Sphere)

  视觉描述:
  - 一个直径可变（280px/340px/400px）的球体
  - 核心层: 半透明球体，内部有流动的光线（使用CSS渐变+动画）
  - 声波层: 3层同心圆环，随音量/语速扩张/收缩
  - 光晕层: 球体周围柔和光晕（box-shadow + blur）
  颜色:
  - 洛神说话时: 电蓝色光晕和波纹
  - 用户说话/等待时: 紫罗兰色脉动
  - 思考中: 缓慢呼吸式明暗变化
  - 出错/无服务: 红色慢闪

  声音驱动:
  通过 Web Audio API 获取实时音频数据（输入/输出）：
  - 麦克风音量（用户说话）→ 紫色波纹强度
  - TTS音频数据（洛神说话）→ 蓝色波纹扩张

3.2 粒子系统 (Particle System)

  位置: 声波球背后，全屏（或主舞台区域）
  数量: 60~100个（移动端40个，桌面端100个）
  行为:
  - 微微飘动（random walk + 边界约束）
  - 当洛神说话时: 粒子向声波球聚拢（模拟信息凝聚）
  - 当用户说话时: 粒子短暂向外扩散再回落（模拟信息接收）
  实现: 轻量级，必须使用 Canvas 2D（不引 three.js。减少加载时间、增加电池续航）
  Canvas 放置于声波球 z-index -1，透明背景叠加。

3.3 情绪色彩映射 (Emotion Color Mapping)

 洛神的 feelings 状态影响背景和声波球光晕颜色:
  ──────────────────────────────────────────
  情绪状态      │ 光晕色        │ 背景变化
  ──────────────────────────────────────────
  平静         │ 柔和蓝 (#4FC3F7) │ 默认深海
  开心/兴奋    │ 明亮蓝+微金    │ 背景微亮
  好奇/求知    │ 青蓝渐变       │ 粒子速度加快
  难过/低落    │ 深蓝灰 (#37474F) │ 背景变暗
  疲惫         │ 暗蓝光晕减弱   │ 背景最暗
  关怀/温暖    │ 暖蓝+淡橙      │ 背景微暖
  烦躁/压力    │ 明度不稳定     │ 闪烁（缓慢）
  未知/无状态  │ 默认蓝         │ 默认深海
  ──────────────────────────────────────────

 实现: Canvas 渲染器监听 WebSocket 推送的 emotion_state 消息。


【四、洛神视觉形象（主舞台形象）】

4.1 设计理念
  洛神不是真人，是信息聚合体。形象优先抽象表达而非具象人脸。
  方案选择: 声波球 + 粒子聚合体（而非虚拟形象/二次元头像）

      position: absolute; inset: 0;

  }

  .ring:nth-child(2) { animation-delay: -1s; opacity: 0.5; }
  .ring:nth-child(3) { animation-delay: -2s; opacity: 0.2; }

4.3 视觉交互反馈

  首次进入页面: 声波球从中心粒子聚拢生成（300ms 粒�子聚合动画）
  收到用户消息: 球体表面短暂波纹（涟漪从边缘向内扩散）
  收到洛神回复: 球体缓慢"呼吸" + 声波环随文本节奏律动
  语音通道连接成功: 绿色微闪一次（视觉提示）
  洛神打断或被中断: 球体颜色短暂过渡（蓝→紫→蓝，300ms）

4.4 降级策略（无 JS / 弱设备）
  - 关闭粒⼦系统
  - 声波球退化为静态 + CSS 渐变呼吸
  - 保留情绪色彩变化（仅 CSS）


【五、跨设备同步架构】

5.1 同步需求
  - 聊天历史同步（新设备打开即可看到历史）
  - 主动行为状态同步（洛神正在发起话题时，其他设备看到状态）
  - 语音通话唯一（同一时间仅允许一个设备发起语音）
  - 用户状态同步（用户正在输入/在线/离线指示）
  - 洛神感知状态同步（最新的 feeling、energy 等信息）

5.2 同步通道设计

  方案: Supabase Realtime (已有基础设施) + 自定义同步协议

  现有系统已有 Supabase 连接（用于消息存储），本方案扩展:

  5.2.1 频道设计

  频道名             │ 用途                │ 订阅方
  ──────────────────────────────────────────────────
  channel:messages   │ 消息增删改          │ 所有客户端
  channel:luoshen_state │ 洛神状态变化      │ 所有客户端
  channel:voice_bridge  │ 语音通话桥接信令  │ 正在通话的设备
  channel:typing       │ 用户正在输入指示   │ 除当前输入设备外的其他设备
  channel:presence    │ 设备在线心跳       │ 所有客户端

  5.2.2 洛神状态广播 (luoshen_state)

  当任一端更新了洛神的状态（feelings、self_core、动机等），广播给其他端:

  {
    "type": "luoshen_state_update",
    "timestamp": 1725097822.0,
    "source_device": "mobile_1",
    "payload": {
      "feelings": ["平静", "好奇"],
      "self_core_version": 42,  // 自 core_state 版本号
      "active_gene": "GENE-001",
      "current_motive": "curiosity",
    },
  }

  其他端收到后更新本地状态，无需再次请求。

  5.2.3 语音通话独占控制 (voice_bridge)

  设计原则: 世界唯一语音通话，任一设备发起时，其他设备自动进入"监听"或"挂起"状态。

  流程:
  设备A发起语音请求:
    1. 设备A → Supabase: SET voice_lock = {device: "A", session_id: "xxx", ts: now}
    2. 其他设备收到 REALTIME 事件 → 检查 voice_lock
       - 若 voice_lock 已被设置且 ts 相差 <30s → 本设备拒绝发起新通话
       - 显示提示: "另一设备正在进行语音通话"
       - 用户可选择: [监听此通话（单向接收）] 或 [等待]
    3. 若原设备30s无心跳 → 自动释放锁定

  语音通话心跳:
    每5秒设备发送心跳 {session_id, audio_level}，更新 voice_lock.ts。

  5.2.4 用户正在输入指示

  在前端键入时（每2秒最多发一次）:
  {
    "type": "typing_start",
    "user_id": "...",
    "device_id": "mobile_1",
    "timestamp": 1725097822.0,
  }

  停止输入3秒后发送:
  {
    "type": "typing_end",
    "user_id": "...",
  }

  显示: "洛神正在听..." 或 "对方正在输入..."（在对方设备显示）。

5.3 跨设备消息传递

  当设备A发送一条消息:
  1. 设备A → Supabase insert message
  2. Supabase Realtime → 其他设备收到 INSERT 事件
  3. 其他设备渲染消息到对话区（无需刷新）

  当洛神回复:
  1. 后端（voice_relay.py 或任何设备调用）→ Supabase insert reply
  2. 所有设备同时收到 reply

【七、菜单与设置（极简整合）】

7.1 设计原则: 一个菜单解决全部设置

  入口: 顶部右上角"≡"按钮（桌面端）/ 底部导航"我"（移动端）
  打开方式: 右侧抽屉（桌面端从右侧滑入，移动端从底部上滑）
  菜单项（仅保留6个，绝不超7个）:

  ┌─────────────────────────────┐
  │  ≡                         │
  ├─────────────────────────────┤
  │  📢 语音通话              │  → 跳转 VoiceCall
  │  🔄 同步状态              │  → 强制重新拉取
  │  🎨 视觉密度              │  → 省点/标准/完整
  │  🔇 静音 / 通知           │  → TTS开关/主动行为静音
  │  📊 洛神状态面板        │  → 打开/关闭右侧面板
  │  ℹ️ 关于洛神              │  → 版本/哈希链验证状态
  └─────────────────────────────┘

7.2 视觉密度三级切换

  省电模式: 关闭粒子、关闭声波环动画，仅保留色彩呼吸
  标准模式: 粒子 + 声波呼吸环（默认）
  完整模式: 所有声波/光晕效果全开

7.3 静音模式

  独立控制（TTS / 主动行为）:
  - TTS 关闭: 文字语音双输出  → 仅文字输出
  - 主动行为静音: 不再发起主动问候/分享，仅在响应模式

【九、加载/错误状态设计】

9.1 加载状态
  对话加载: 3个粒子从声波球内飞出，组成"加载中"文字（简短显示）
  网络延迟 >800ms: 球体颜色微微变红，文本渲染"网络延迟中..."

9.2 错误状态

  LLM 不可用:
    球体震动3次 + 气泡显示[通信受阻]
    → 10秒后自动重试1次
    → 若再失败，显示[洛神暂时无法回答，请稍后再试]

  ASR 不可用:
    声波区域显示麦克风图标 + 斜杠
    → 降级到原生的浏览器识别，若无则纯文字输入

  TTS 不可用:
    球体右下角显示静音图标
    → 所有语音回复转为文字卡片

  哈希链断裂:
    顶部红色横幅: "系统日志出现异常，请检查"
    → 洛神可不继续写入，但仍响应用户交互


【十、性能预算与实现约束】

10.1 帧率目标

  场景                  │ 目标
  ──────────────────────────
  粒子系统              │ 60fps (桌面), 30fps (移动省电)
  声波呼吸动画          │ 30fps（低频率足够）
  LLM文字流          │ 逐字符不卡
  折叠屏布局切换        │ 过渡 <200ms

10.2 包体积预算

  项目组件                │ 预算
  ──────────────────────────
  React + 当前已有依赖    │ 现有
  新增: framer-motion     │ ~30KB (仅用于布局切换，不用于粒⼦)
  新增: zustand           │ ~3KB (跨设备状态管理)
  总打包体积              │ < 300KB gzipped

10.3 电量优化

  移动设备上:
  - Canvas 粒⼦帧率上限30fps
  - 当 Tab 不在活跃状态 >5s 时，粒⼦系统暂停
  - WebSocket 心跳间隔从5s降至15s

  省电模式下:
  - 粒⼦数量从60减至20
  - 关闭声波环动画
  - 关闭 WebSocket 持续连接，切换为5秒轮询
